# 1. Project Overview

## What is Lenguo?

Lenguo is a language-learning mobile application.

The main idea is to help the user learn vocabulary through different categories, with support for Arabic and English.

The application currently includes:

* Authentication
* Language selection
* Vocabulary categories
* Vocabulary words
* Vocabulary details
* Text-to-Speech
* Arabic / English content switching

# 3. Project Architecture

I used Clean Architecture.

Each feature is divided into:

```text
data
domain
presentation
```

The general flow is:

```text
UI
 ↓
Cubit
 ↓
UseCase
 ↓
Repository
 ↓
DataSource
 ↓
External Source
```

The reason for using this architecture is to separate responsibilities.

The UI should not directly communicate with Firebase, SharedPreferences, or JSON files.

---

# 4. Data Layer

The data layer is responsible for communicating with external data sources.

Examples:

* Firebase Authentication
* SharedPreferences
* Local JSON files

The DataSource communicates directly with the external source.

The Model represents the data received from that source.

Example:

```text
Firebase
   ↓
AuthDataSource
   ↓
AuthModel
```

---

# 5. Domain Layer

The domain layer contains the application's business logic.

It contains:

* Entities
* Repository interfaces
* UseCases

The domain layer should not depend on Firebase, Flutter UI, or SharedPreferences.

Example:

```text
Entity
   ↑
Repository Interface
   ↑
UseCase
```

---

# 6. Presentation Layer

The presentation layer contains:

* Screens
* Widgets
* Cubits
* States

The UI communicates with the Cubit.

The Cubit communicates with the UseCase.

Example:

```text
Screen
 ↓
Cubit
 ↓
UseCase
```

---

# 7. Dependency Injection

I used:

* GetIt
* Injectable

Instead of manually creating dependencies everywhere, I registered them using Injectable.

Important annotations I used:

```dart
@injectable
@lazySingleton
@Injectable(as: SomeInterface)
@module
@preResolve
```

The main initialization is:

```dart
@InjectableInit()
Future<void> init() async {
  await sl.init();
}
```

It is important that `await sl.init()` is called before using dependencies.

The generated file:

```text
injection.config.dart
```

contains the actual registrations generated by Injectable.

---

# 8. Error Handling

I separated Exceptions from Failures.

## Exceptions

Exceptions are used in the Data Layer.

Examples:

```dart
ServerException
CacheException
```

## Failures

Failures are used after the Repository layer.

Examples:

```dart
ServerFailure
CacheFailure
```

The general flow is:

```text
External Error
     ↓
Exception
     ↓
Repository
     ↓
Failure
     ↓
Cubit
     ↓
State
     ↓
UI
```

# 9. Firebase Authentication

Authentication is implemented using Firebase Authentication.

The authentication feature contains:

* Login
* Register
* Forgot Password
* Logout
* Google Sign-In placeholder

---

## Login Flow

```text
Login Screen
     ↓
AuthCubit.login()
     ↓
AuthLoginUsecase
     ↓
AuthRepository
     ↓
AuthDataSource
     ↓
FirebaseAuth
```

Firebase errors are caught in the DataSource.

I created:

```text
FirebaseErrorMaper
```

to convert Firebase error codes into user-friendly messages.

For example:

```text
FirebaseAuthException
        ↓
FirebaseErrorMaper
        ↓
friendly message
        ↓
ServerException
```

The Repository then converts the Exception into a Failure.

# 11. Language Selection

The application supports two learning directions:

* Arabic
* English

I decided to store the selected language locally using SharedPreferences.

I used the key:

```text

```

The stored values are:

```text

```

---

# 12. Why SharedPreferences?

The selected language is a small local setting.

It does not need a Firebase database.

Therefore, SharedPreferences is enough for storing it locally.

The flow is:

```text
User selects language
        ↓
LanguageSelectionCubit
        ↓
SetLanguageUseCase
        ↓
Repository
        ↓
DataSource
        ↓
SharedPreferences
```

---

# 14. CurrentLanguage

I needed different features to know which language is currently selected.

Instead of making every feature communicate directly with SharedPreferences, I created:

```dart
abstract class CurrentLanguage {
  String? get languageCode;
}
```

`LanguageSelectionCubit` implements this abstraction.

This allows other parts of the application to ask for the current language without depending directly on the DataSource.

The dependency flow is:

```text
LanguageSelectionCubit
        ↓
CurrentLanguage
```

The same Cubit instance is provided through Dependency Injection.

---

# 15. Language-Dependent UI

To determine the current language:

```dart
final currentLanguage = sl<CurrentLanguage>();

final isArabic =
    currentLanguage.languageCode == 'ar';
```

Then the UI can decide which content to display.

Example:

```dart
isArabic
    ? arabicContent
    : englishContent;
```

This allows the content of different features to change based on the selected language.

# 21. Text-to-Speech

I used:

```text
flutter_tts
```

The application chooses the TTS language based on the current learning language.

Arabic:

```text
ar
```

English:

```text
en-US
```

The process is:

```text
User presses speaker
        ↓
stop previous speech
        ↓
setLanguage()
        ↓
speak()
```

Before speaking a new word, I stop the previous speech:

```dart
await flutterTts.stop();
```

The TTS instance is also stopped when the screen is disposed.

# 22. Problems I Faced

## Problem: LanguageSelectionCubit was not registered

Error:

```text
Bad state: LanguageSelectionCubit is not registered
```

### Cause

Dependency Injection initialization was not being awaited correctly.

### Solution

I changed the initialization to:

```dart
await sl.init();
```

This made Injectable finish registering the dependencies before they were used.

---

## Problem: Current Language

I needed other features to know whether the current language was Arabic or English.

### Solution

I created:

```dart
CurrentLanguage
```

and made:

```dart
LanguageSelectionCubit
```

implement it.

Then Injectable registers the same Cubit instance as `CurrentLanguage`.

---

## Problem: Arabic Text-to-Speech

Arabic TTS was not initially working as expected.

I checked the available TTS engines on the Android device and configured the device's speech engine/language support.

After that, Arabic and English speech worked.

# 23. Important Architecture Decisions

## Why Cubit?

I use Cubit because the state changes in this project are relatively straightforward.

I don't need event-based Bloc for every feature.

---

## Why Clean Architecture?

I wanted to keep:

```text
UI
Business Logic
Data
```

separated.

This also makes the project easier to maintain and change later.

---

## Why JSON for Vocabulary?

Vocabulary is currently static content.

Using local JSON makes it easy to:

* Add categories
* Add words
* Change translations
* Add images
* Keep the data separate from UI code

For example, adding another category can be done by creating:

```text
fashion.json
school.json
animals.json
```
